# Live differential: unsigned completion plan

`npm run differential:plan` compiles the existing Clean, OriginHint and Counter probes with the pinned, hash-checked Solidity 0.8.24 compiler, checks their source and bytecode against the local ledger, verifies Hadrian chain ID 200010, and requests read-only deployment gas estimates. Its output is [`evidence/unsigned-differential-plan.json`](../evidence/unsigned-differential-plan.json). It never signs or sends.

The JSON contains full creation bytecode, exact call calldata and projected contract addresses for account `0x765fb7e6a0BdDDc29f57eeCE34AEda0Fb318805d` at pending nonces 4, 5 and 6. The projected addresses change if another transaction consumes a nonce or the order changes. At block 519617431, deployment gas estimates were Clean `3494881`, OriginHint `2296001`, Counter `3271361`; padded gas limits were `4543345`, `2984801`, `4252769`. At the sampled gas price, the combined deployment cap was `2.008043189153510100` test USDC, above the sampled `1.734611224783532832` balance. Calls are additional, and their gas/fees cannot be quoted against undeployed addresses. **Final budget is therefore BLOCKED.** These values are dated estimates, not spending authorization.

After separate owner approval and adequate testnet funds, the owner would check the live chain ID, nonce, predicted addresses, calldata and fresh MetaMask gas/fee quote before each of three deployments. After each receipt and code are verified, estimate and approve the corresponding `add(2,3)`, `origin()`, or `increment()` call separately. Record transaction hash, receipt status, deployed code, decoded output/event, and state readback at the receipt block. Then run a new local EVM execution, normalize sender and block context, compare observed behavior, and rerun regression against the previous evidence. Stop on any mismatch. Do not use this draft to sign or submit automatically.
